# OEPS Scanner v0.2.0

Adds Bluetooth barcode-reader input, Odoo and supplier labels, raw fallback, and command labels to the Windows scanner.

## Install or update

Download **OEPS.Scanner-0.2.0-setup-win-x64.msi** for a complete per-user installation of the server, test client and bundled runtimes. Existing users can accept the launcher's update offer after closing both applications. Camera and reader preferences are preserved. Both GUIs display v0.2.0 at the bottom right.

## New in this release

- Bluetooth SPP reader configuration, including outgoing-port discovery and remembered reader selection. Tested during development with an Inateck BCST-73.
- Separate WebSocket endpoints: camera on port **8765**, barcode reader on **8766** by default. Both are configurable. Connecting a client opens its source; one minute without clients closes it unless its debug override is enabled.
- Barcode-reader scans have **no duplicate suppression**. Fast mode separates CR+LF-terminated scans immediately; a multiline mode is also available. Camera readings retain the **500 ms** per-payload filter for every label version.
- Version **2**: Odoo sales order and OUT record IDs and printed document numbers, protected by CRC-32.
- Version **3**: Worldway and supplied Farnell/Mouser/DigiKey formats. Requires valid quantity and at least one valid OEPS PN or nonempty MPN; missing identifiers become JSON null.
- Version **C**: `C*<command>*<checksum>`, producing only `label_version` and `command`. Names are extensible; the client decides what they do. Example: `C*For Odoo OUT*14C79D4D` produces `{"label_version":"C","command":"For Odoo OUT"}`.
- Version **X**: any reading that fails versions 1/2/3/C is forwarded as original raw text, preserving control characters and Unicode. Clients decide whether to use it.
- Camera decoding supports Data Matrix, QR, Aztec and linear barcode formats. Updated preview, diagnostics and in-app label-format reference.
- Existing version 1 payloads and JSON remain supported.

## Client integration

Replace **both** `Scanner.Client.dll` and `Scanner.Contracts.dll` using **OEPS.Scanner.Client-0.2.0.zip**. Older SDKs reject the new versions. The ZIP includes XML documentation, README and example; .NET 10 is required. `ConnectAsync`, `JsonReceived`, `LabelReceived`, `StateChanged` and `CloseAsync` keep their existing APIs. Select camera or reader using the port argument.

For commands, use `IsCommand` and `Command`; the wire version is the string `"C"`. For raw readings, use `IsRaw` and `Raw`; the wire version is `"X"`. Numeric versions 1/2/3 remain numeric. Commands are forwarded, never executed by the scanner.

The application ZIP is for the automatic updater; use the MSI for a fresh installation. SHA-256 sidecars accompany the installer, application ZIP and SDK ZIP. NuGet packages are also included as release downloads.

## Known limitation and next release

Reader **Connected** currently means its COM port opened successfully. Serial errors trigger cleanup and reconnection, but switching off a Bluetooth reader can leave that status unchanged if Windows continues returning read timeouts. Independent Bluetooth connection monitoring, clearer status and recovery after confirmed Bluetooth loss are deferred to the next release. Lack of scans will not be treated as a lost connection. Physical power-off/reconnection verification will require the BCST-73.

Automated checks cover contracts, checksum vectors, real WebSocket delivery, source isolation, rapid reader repeats, camera filtering, GUI layout and update recovery. Clean-machine installation and physical scan/power-off behaviour remain separate operator checks.
