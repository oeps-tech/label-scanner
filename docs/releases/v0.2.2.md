# OEPS Scanner v0.2.2

Adds separate barcode formats for Odoo sales orders and deliveries, with matching server validation, client SDK support and GUI references.

## Install or update

Download **OEPS.Scanner-0.2.2-setup-win-x64.msi** for a full Windows x64 installation. Existing installations can accept the launcher's update offer. Close both server and test client before updating. Settings are preserved, and both applications display v0.2.2.

## Separate Odoo documents

- **Version 4** identifies a sales order using its internal `sales_order_id` and printed `document_name`: `4*857*S/2680*71878073`.
- **Version 5** identifies a delivery using its internal `out_id` and printed `out_number`: `5*1923*WH/OUT/00567*D3BF0810`.
- Both formats use version 2's validation rules: positive integer IDs up to 2147483647, nonblank printable ASCII document numbers, a 4,096-character payload limit and CRC-32/IEEE over the exact first three fields and separators. Spaces and case are preserved; invalid labels become raw X.
- JSON contains exactly the numeric `label_version`, the relevant record ID and its printed number. No checksum or fields from the other document are sent.
- The test client displays the relevant fields, and the server's **Label versions & JSON** reference includes both formats and examples.

For sales orders, use Odoo's printed **`document_name`**, not `name`. The scanner does not contact Odoo or open records; consuming applications use their configured Odoo address and the supplied ID.

## Compatibility and downloads

Update the server and **both client DLLs** to v0.2.2 to use versions 4/5. Older client DLLs reject those versions. Existing versions 1/2/3/C/X, connection APIs and WebSocket ports retain their behavior. Camera readings retain the 500 ms duplicate filter; every reader scan is sent, including identical repeats.

**OEPS.Scanner.Client-0.2.2.zip** contains both .NET 10 client DLLs, documentation and an example. The application ZIP is for the automatic updater; use the MSI for a fresh installation. SHA-256 sidecars and the two NuGet packages are also available.

Automated coverage includes independent CRC examples, validation boundaries, strict JSON schemas, mixed-version SDK delivery over WebSocket, reader repeats, camera filtering and mixed/rotated Data Matrix decoding. Physical barcode scans and clean-machine MSI installation remain separate operator checks.
